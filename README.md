# 极端作业健康预警

山火、高原与高温演训现场网络不稳定。本系统把任务前冻结的阈值、设备校准与
风险方案下发到边缘设备，由边缘端**离线**接收生命体征片段并给出带模型版本与
输入窗口的风险预警；恢复连接后再按设备序列号安全汇入。时间漂移、传感器失联
与相互矛盾的读数只会降低置信度并留痕，系统绝不补造数据。

## 设计原则

- **任务前冻结**（`protocol.py`）：阈值、校准、规则、置信度扣减、处置阶梯
  全部属于冻结协议，内容指纹（SHA-256）随每条预警携带；高温
  `heat@2026.09.01` 与高原 `altitude@2026.09.01` 各一套。阈值更新必须升
  版本号，旧方案原样保留，旧判断永不被重写。
- **边缘离线评估**（`engine.py`）：60 秒输入窗口 + 15 秒定稿宽限；窗口内容
  只取决于样本集合与各自的接收时刻 `rx_ts`，与喂入顺序无关。乱序、重复
  （按 `设备序列号:序列号` 幂等）回放得到**同一条**风险时间线。
- **异常只降置信度，不补造**：传感器失联、多设备读数矛盾（超冻结容差）、
  时钟回退（超冻结抖动）、越界值分别标记并扣减置信度；置信度低于阈值时，
  高危建议自动降级为现场复核。系统不插值、不在矛盾设备间"挑顺眼的"。
- **迟到不重写**：超过定稿截止（窗末+宽限）才到达、或定稿后才送到的样本，
  只追加 `late_supplement` 补充记录；已定稿评估的哈希保持不变。
- **处置阶梯**（`oversight.py`）：高危信号依次触发
  现场复核 → 降温补水 → 转运，自动方向只升不降。值班军医可以覆盖建议
  （含解除），但**必须填写理由**并不可变留痕；每次动作都锚定当时的模型
  版本、校准指纹、阈值指纹与命中规则依据。
- **安全汇入**（`edge.py` / `sync.py`）：边缘出站记录成哈希链；服务端校验
  协议指纹、逐记录重算哈希、检查 node_seq 连续性（有缺口只拒绝、不猜测
  补缺）、按规则对账重算命中与动作；全量重放幂等，篡改任一字段即拒绝，
  批次要么整体生效要么整体回滚。`coverage` 按设备序列号报告覆盖段与缺口。
- **最小知情视图**：指挥人员只看到 `谁/状态/所需动作/是否被军医覆盖`，
  看不到血氧体温明细与健康档案；卫生员多一层现场复核要点；军医可见完整
  触发依据与审计链。
- **不可变留痕**（`store.py`）：评估、迟到补充、处置、覆盖、同步批次都在
  只追加哈希链上，任何改写都能被 `verify()` 发现。

## 模块

| 文件 | 职责 |
|---|---|
| `domain.py` | 角色、状态、通道、处置阶梯、质量标记常量 |
| `protocol.py` | 冻结协议、内容指纹、高温/高原方案、版本登记簿 |
| `store.py` | 只追加哈希链存储与防篡改校验 |
| `engine.py` | 离线窗口评估、质量判定、确定性定稿、迟到补充 |
| `edge.py` | 边缘节点、出站哈希链、批次导出与确认 |
| `sync.py` | 恢复连接后的链校验、序列连续性、规则对账、覆盖报告 |
| `oversight.py` | 处置升级、军医理由覆盖、审计、角色视图 |
| `scenario.py` | 高温/高原既有事件切片（含乱序、重复、失联、矛盾、漂移、越界、迟到） |
| `system.py` | 装配登记簿、节点、同步与监督 |
| `service.py` | HTTP 入口（内存态，供联调） |

## 运行与验证

```bash
python3 service.py --check          # 基础配置检查
python3 service.py --port 8000      # 启动服务
npm test                            # 全部 51 个单元/契约/场景测试
python3 scenario.py --emit-fixtures fixtures   # 重新生成事件切片
```

主要接口：`GET /protocols`、`POST /nodes`、`POST /nodes/{sn}/feed`、
`POST /nodes/{sn}/tick`、`POST /nodes/{sn}/sync`、
`GET /nodes/{sn}/timeline`、`GET /nodes/{sn}/coverage`、
`POST /dispositions/override`（理由必填）、
`GET /view?role=指挥人员`、`GET /audit`。`GET /health` 保持原契约不变。

`fixtures/heat_event.json` 与 `fixtures/altitude_event.json` 是确定性切片，
预期时间线均为 `监测 → 现场复核 → 降温补水 → 转运`，可反复以乱序/重复方式
回放验证一致性。

字段称谓见 `fixtures/domain.json`；业务记录只由正式引擎产生。
